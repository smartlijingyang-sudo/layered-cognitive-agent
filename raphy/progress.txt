## Codebase Patterns

- **重叠 CLI 命令先按输出格式分类再决定 merge vs cross-reference（RA-108）：**
  ``journal step --step N``（单步原始事实纯文本）与 ``journal steps --step N``
  （StepNarrativeWriter narrative markdown）输出本质不同且都被 docs/ADR 引用 →
  选 (b) 保留双命令、共享 ``read_step_document`` + ``JournalDocument.step_by_index``
  typed seam，帮助文本互相交叉引用。收敛 raw-dict 读取前用
  ``dataclasses.asdict(JournalStep)`` 对比渲染：key 顺序与 journal.json 原始
  dict 完全一致，human 与 ``--json`` 输出字节等价，可放心删私有
  ``_load_journal``/``_select_step``。

- **模型身份是 LLMAdapter 契约成员，不是私有字段（RA-106）：** telemetry 的
  ``model=`` 标签必须来自协议声明的 ``model_name`` accessor，不能 getattr 私有
  ``_model``。协议默认实现返回 ``None``（而非 raise NotImplementedError）——
  因为已有 ``getattr(adapter, "model_name", None)`` 消费者（model_visible
  adapter 的 ``_resolve_model_config``），默认 raise 会炸掉它。生产适配器
  （openai_compat/anthropic 策略/mock/model_override）覆写返回真实模型 id。
  同类私有探针残留：``think/reasoner/credentials.py:131`` 与
  ``cli/commands/runs/driver_debug.py:190`` 仍读 ``_model``，可后续顺手收敛。

- **Package contract enforcement must scan actual imports（RA-107）：**
  `check_package_contracts.py` 的 L1↔L2 cross-check 只验证 README *提到* 了
  forbidden dep，从不扫描真实 import——`lca.application` 契约禁
  `lca.harness` 而 `runtime/` 一直在 import，静默违规。全仓 actual-import
  扫描揭示 142 处既有 forbidden-dep 违规：package contract 普遍是理想声明。
  修法：组合根的契约按真实 wiring 更新（允许 harness+plugins，只禁
  gateway），再把 `check_actual_forbidden_imports` 接进脚本 main() 做强制。
  验证时用 `--package <pkg>` 聚焦本 story 包，其余违规记为基线。

- **环境输入（cwd）绝不能冒充诊断输入（RA-060）：** `run(profile_path)` 接受参数又
  `del` 掉、转去读 `Path.cwd()`，是典型的环境泄漏进纯诊断域。修法：repo root
  必须从 profile_path 派生（walk-up 找 repo marker）或显式传入；找不到 marker
  时回退到 profile 自己的目录（仍由输入派生，C8 确定性成立），绝不回退到 cwd。
  显式传入的 repo_root/check_script 优先级最高，派生逻辑不得搬动它们。

- **能力探测走已声明的方法，不要给 Protocol 加实现细节属性（RA-059）：**
  想在 Protocol 上声明 `root: Path` 会逼 merged store 撒谎（它没有单一 root）——
  正确做法是把调用方真正需要的操作做成 seam（`materialize_link`），默认
  `raise NotImplementedError`（`update_package_meta` 同模式），只读视图天然退出。
  调用方按需把 NotImplementedError 翻译成自己的域错误（TypeError / _CatalogConfigError）。
  文件存在性这类探测也一样：用已声明的 `get()`（缺文件即 SkillNotFoundError）
  而不是穿透属性。

- **"resolve" 命名的函数绝不能写盘（RA-058）：** 工厂函数的"解析"语义是契约，
  副作用必须拆成显式动词（`materialize_bundled_skills`）并只在 boot 期调一次。
  71515dace 的教训：单测里一次无意的 boot 就把生产 `~/.lca/skills` 重写了，
  而纯函数测试永远看不见"谁在何时调用"。effect 声明（filesystem）要挂在
  真正写的那一步上，不是挂在构造上。

- **写守卫挂"谓词+消息"二件套，别改 is_standing_write_path 本体（RA-057）：**
  新守卫（技能包）在 `standing_path.py` 里与 `is_standing_write_path` 并列加
  `is_<x>_write_path()` + `<x>_write_block_message()`，三个写调用点
  （policy.validate_writable_file、executor.write_file/edit_file）各加一段
  check。别把新形状塞进旧谓词——block message 必须点名生产工具
  （create_assistant_skill/edit_assistant_skill），混在一起消息就没法区分。

- **digest 约定收敛先定 canonical 函数再改写入点（RA-056）：** 同一字段出现两种
  hash 约定时，不要逐个改写入点——先在共享层立一个 canonical 函数
  （`skill_index_digest(content_hash) -> sha256:<hex>`），把"约定"写成代码，
  再让所有写入点调用它。旧数据用"版本标记 + 读时一次性迁移"
  （`skills_index_digest_version`，缺失=旧约定），别留双约定并存窗口。

- **metadata 走私 → typed kwargs 迁移纪律（RA-033）：** envelope metadata
  只放 JSON 友好的 id/ref 标量；需要活对象的 handler 从
  `EffectHandler.handle` 的 keyword-only 参数拿（`state`/`decision`/
  `observation`/`reflection`），dispatcher 经 `execute(**handler_kwargs)`
  原样转发。新增 effect 操作时 handler 签名直接加 kwarg，不要回头往
  metadata 塞对象。fail-loud：handler 缺必需 kwarg 时 raise
  DeclarativeValidationError（PG-003），不要 KeyError 裸奔。

- **port 迁移先查生产者（RA-042 血训）：** 把 metadata 走私改成 typed port
  时，必须先确认该 port 全图有生产者——`state` port 无任何写入方，
  RA-033 删 smuggle 后 effect.execute 拿到 None，PG-003 让所有工具调用
  静默死亡。迁移前 grep `PortName("<name>")` 的写入点；无生产者就用
  `lca/nodes/_resolve.py::resolve_typed_port_or_runtime`（port 优先、
  kernel runtime carrier 兜底，think/decision/parse 同款）。

  验收模糊或直觉与实现分歧时，以显式 case 表 + 零语义变更为准。

  `LoopObligationExceededError: plan/edge/taken` 事实，`extra["loop_obligation"]` 存
  {plan_id, edge{source,target}, max_iterations, taken}，total_steps=taken，budget_used 保持零值
  Budget（Result 契约：非 COMPLETED 即零值）；`asyncio.CancelledError` 仍在前置分支透传，

  graph loop bound。新纯函数 `lca/framework/graph/loop_budget.py::clamp_loop_bounds(plan, max_steps)`，
  `DeclarativeExecution.execute` 在 `lift_graph_spec` 后调用：每条 loop edge 的有效 bound =
  `min(plan.loop.maxIterations, state.budget.max_steps)`，只收紧不放松。选 (a) 不选 (b) 的原因：
  run() 的 execute() 是单次 await，agent 层无法在中途计数步数主动 break；graph 层是唯一能观察
  loop take 的地方——复用现有 LoopObligationExceededError 机制而非另造步数计数器。
  Frozen plan 用 model_copy，bindings 持有的编译产物不动。
