## Codebase Patterns

（raphy 轮共享的模式/禁区登记，供后续 assess/optimize 轮参考）

- **禁区（ralph Round 2 领地 + 冻结区）：** DecisionGates、Ingest、ContextFiles shims、
  Read Runs micro-dirs（`plugins/transport/webserver/read/runs/`）、MemoryTools directory seam
  （`infrastructure/tools/assistant/`）、`lca/cognition/memory/`（Round 2 AP-01 冻结）。
- **禁区（活跃迁移领地）：** lca-1000 轮（`contracts/event.py` PILOT 事件分类法、
  `plugins/transport/webserver/` 退休 stub 删除）；iter lanes 2026-10-07 刚动过
  `DelegationCacheHit` 接线，RA-012 开工前先 `git log` 确认无并发修改。
- **禁区（他人工作）：** `gate_chain_strategy.py` 绝不动（2026-10-07 09:00 轮事故：
  误 `git checkout --quiet .` 抹掉他人未提交改动；铁律：绝不以任何命令丢弃他人未提交内容）。
- **刻意规则：** CLI surface 不 import contracts（`projection.py:22-23` 注释）；
  `CursorRecord` 类级 `_cursor` 是 ADR-0185 spec section H 显式 DI；
  `_snapshot_from_state` 是包内刻意 internal seam（防两 cursor 实现漂移）。
- **已收敛 idiom：** "converge N identical X"（RA-001/RA-002/RA-008 及 iter-quality 的
  `_TURN_ENDED`、`add_observer_hook` 守卫、`_session_id`/`_turn_of` 等）；新 duplication
  候选先确认真有簇（`CacheConfig(enabled=False)` 全仓一处 → 不开 story）。
- **change-gated listener 判定（RA-010）：** 用 ``!=``（值语义）判 deriver state
  变化，与 ``ProjectionRegistry._drive_unit`` 同款纪律；reducer 纯度（返回等值
  新对象）下 ``!=`` 不误报，``is not`` 会误报——默认 deriver 全是 frozen
  dataclass，``!=`` 天然正确。

- **session attach ritual 顺序分歧（RA-019 待定）：** title_service
  `attach_to_store` 先 `require_observer_hook` 再遍历（fail-first，无部分挂入），
  其余四家（projection_cache / telemetry_capture / spine_anomaly /
  projection_registry）先遍历再 require；RA-019 收敛时定 canonical 顺序。
- **sandbox `destroy()` 是 terminal：** `unbind_sandbox_runtime` 先 pop
  再 destroy，被 destroy 的实例永不复用——`_stateless` 不重置不是 bug，
  后人勿重提（2026-10-07 Round 6 误报教训）。
- **`_run_inspect_internal` deferred import 已证无 cycle（RA-020）：**
  skills.format.routing / workspace 三种顺序 fresh-interpreter 探针全过；
  guilty-until-proven-innocent 对此二模块已证 innocent。
- **`_revision_of` 两处观察：** tool/overlay.py 私有 vs
  skill/overlay/gating.py（包内共享）；第三处出现再开 story。
- **kernel 事件字面量 ≠ session surface 词表：** turn/step/message.*.v1
  属 `lca_kernel.events.session.session`，勿收进 session 包做 single
  source（RA-017 的层向论证不适用；Round 4 "注释自称 single source"教训）。

- **model_visible payload forward-ref 缺陷位（RA-024 认领，optimize 前勿动）：**
  `lca_kernel/events/payloads/model_visible.py` 的四名（AssistantRequestConfig /
  MessageDict / ToolCallDict / UsageDict）只在 TYPE_CHECKING 块 stub 为 Any，
  字段字符串引用 pydantic v2 不解析；`hook.py` 与 `fold_source.py` 各有一份
  import-time rebuild 仪式，`publisher.py` 的 eager import（`noqa: F401`）
  纯为触发副作用。修法是源头自愈，不是第三处仪式。
- **step_id `step-{n:03d}` 四处独立派生（RA-025 认领）：** `hook._step_id_for` /
  `plugins/primitive/llm_call/invoke.py:116` / `nodes/think/llm/invoke.py:190` /

- **SchedulerFileLock 收敛残留（RA-026 认领）：** 两调度器各留逐字相同的
  `_acquire_lock`/`release_lock` 直通对（`release_lock` 公开，被
  `tests/integration/proactive/test_pipeline.py` 用 6 次，保留；`_acquire_lock`

  零外部引用（含 tests）。
- **fold.py 五章 N/A guard 同一仪式（RA-027 认领）：** 5 个 `_render_*` 各重复

- **P0 已钉（RA-023 认领，最高优）：** `LoopObligationExceededError` 逃逸

- **运行时验证基线（2026-10-08，MockLLMAdapter，LLM_API_KEY=dummy）：**
  basic run / tool-call run / 同一 agent 双 run 全 completed；P0 复现仍在。
