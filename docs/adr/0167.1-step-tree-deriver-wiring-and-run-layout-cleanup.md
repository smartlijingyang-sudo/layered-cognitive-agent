# ADR-0167.1: Step-Tree Deriver Wiring 与 Run Layout 收尾

- 状态: Accepted
- 日期: 2026-09-02
- 作者: coding-agent
- 收束: ADR-0167 D11 I-MV3 (Re-  ≡ finalize) 的最后一段空白 — deriver 没真正被 wire, 业务 facade 仍在写一条 dead path

## 背景

### ADR-0167 Accepted 后时,生产 runtime 实际上是什么样

| 期望 (ADR-0167 D11) | 实际 trunk 行为 | 后果 |
|---|---|---|
| events.jsonl 是 SSOT (唯一 append-only) | ✓ `spine.sink.file` 写到 `traces/runs/<id>/events.jsonl` | — |
| journal.json 由 `StepTreeAccumulatorDeriver` 累积 events 后落盘 | ❌ `spine.deriver.step_tree` 是 boot-time stub, 永远记 0 step, flush 写空 ` journal.json` | 395 个 run 中 **143 个缺 journal.json, 194 个是空 document**; doctor H2 误报 "jsonl empty or missing" |
| Agent 唯一写路径 = `StepCoordinator` (D2 / I-PLUG1) | ❌ facade `step_open / record_* / close_step / close_document / get_lifecycle_store` 全部转发到 `step_lifecycle.StepLifecycleStore`, 而业务代码从不调 facade 这套 | facade step API 永远空转; spine events 由另一套路径生产, 两套系统互不相通 |
| Step-tree backend 写 journal.json | ❌ `StepGroupedBackend.flush()` 调 `store.close_and_finalize()`, 但 `store.document` 永远是 None, flush 是 no-op |  |
| spine.core 不应订阅 per-run deriver (deriver 需要 run_dir / agent_role) | ❌ `spine.core.setup` 在 boot 阶段对 `_OPTIONAL_DERIVER_KEYS` (step_tree / narrative / graph / live_tail) 一次性 subscribe 全局 stub | events 进 stub; 真正的 per-run deriver 永远没挂上 |
| RunLocator 暴露 journal_step_path / events_path 两条 | ❌ `RunLocator.journal_path` 返回 `journal.jsonl` (legacy raw stream); doctor 与 CLI `_resolve_journal_artifact` 沿这条路径, 但 ADR-0165.1 已把它移到 `events.jsonl` | doctor 找不到 events.jsonl, 走 legacy `journal.jsonl` 失败 |

### 设计尊严条款违反 (D13 B1–B10)

| 违反 | 表现 |
|---|---|
| B1 唯一装配 | spine.core 在 boot 阶段订了一组 stub, transport 在 run 阶段订了一组真 deriver, 同一个 `step_tree` capability 被假装装在两处 |
| B3 显式栈 | `StepCoordinator.close_document` / `_accumulator_document` 用 `getattr` 鸭子类型兜底, 假装 document |
| B5 dataclass 寿命 | `StepTreeAccumulatorDeriver._to_jsonable` 与 `StepGroupedProjector._to_jsonable` 是两份完全一样的递归 dataclass → dict |
| B7 一 plugin 一目录 | `spine.deriver.step_tree` plugin 只生产 stub, 真正的 SSOT 累积器藏在 infrastructure 深处, 没人 subscribe |
| B9 无过渡期两边写 | StepLifecycleStore 在 facade 路径写一份, spine 在 spine 路径写另一份 — 两份都没拼成完整 step tree |

## 决策

### D1. 单一事件真相 + 单一落盘路径

```
Agent intent → StepCoordinator (唯一入口, ADR-0167 D2)
                   │
                   ▼ 五面矩阵: Emitter → Driver → Coalescer → Serializer → Storage
                                                                          │
                                                                          ▼
                                                            RoutingFileSink → events.jsonl (SSOT)
```

events.jsonl 是 spine 唯一 append-only 落点 (D1)。不再有平行 `journal.jsonl`。

### D2. deriver 是 per-run 的, 由 transport 装配

`spine.deriver.step_tree` 这个 plugin (boot-time stub) **删除**。理由: deriver 需要 `run_id / run_dir / agent_role / strategy_key / plan_ref`, 这些是 per-run 数据, 必须在 transport 准备 run 时才能构造。

新装配位置: `RunSessionBuilder.build` 阶段
```python
deriver = StepTreeAccumulatorDeriver(
    run_id=run_id, run_dir=locator.run_dir(run_id),
    agent_role=..., strategy_key=..., plan_ref=...,
)
event_spine.subscribe(deriver.on_event)
```

不在 `spine.core.setup` 订阅任何 per-run deriver。 boot-time 仅剩 process-wide deriver (anomaly, console 等)。

### D3. 单一 journal.json 落盘者

**只有 `StepTreeAccumulatorDeriver.flush()` 写 `journal.json`。** 旧 `StepGroupedBackend` / `StepGroupedProjector` (依赖 `StepLifecycleStore.document`) 整条链路删除:
- `lca.runtime.step_lifecycle.StepLifecycleStore` (428  428 行) — 删
- `lca.infrastructure.observability.journal.step.backend.StepGroupedBackend` — 删
- `lca.infrastructure.observability.journal.step.projector.StepGroupedProjector` — 改名 `JournalDocumentWriter` (去 "StepGrouped" 前缀, 因为不再 group, 直接写)
- `lca.infrastructure.observability.spine.derivers.step_tree.StepTreeDeriver` (legacy stub 包装 backend) — 删
- `lca.plugins.observability.spine.derivers.step_tree` (plugin) — 删

### D4. facade 不再 step_lifecycle

`facade.step_open / step_record_* / step_close` 全部转发到当前 bind 的 `StepCoordinator` (走 ContextVar)。 `step_close_document / step_get_lifecycle_store` 删除 (`StepCoordinator` 不持有 document; 收口由 `StepTreeAccumulatorDeriver.flush()` 完成)。

`StepCoordinator` 增 5 个 record_* 方法 (`record_thinking / record_tool_call / record_tool_result / record_reflect / record_span`), 各自产生一个 spine EP (`step.thinking.record` 等), 加入 EXECUTION_POINTS whitelist。

### D5. RunLocator 双路径

```python
class RunLocator(L:
    def journal_path(run_id) -> Path: ...   # → journal.jsonl (legacy raw; 仅 boot 期 rename 用)
    def journal_step_path(run_id) -> Path: ...  # → journal.json (step-tree 主存储)
    def events_path(run_id) -> Path: ...        # → events.jsonl (ADR-0165.1 SSOT) — 新增
```

`journal_path` 保留 (rename 用), 但 CLI / doctor 不再用它作 lookup path。

### D6. Doctor 与 CLI lookup 顺序

`docs/observability/cli-reference.md` 的 `_resolve_journal_artifact` 顺序:

```
1. --journal (显式)
2. traces/runs/<id>/journal.json       # step-tree 主存储
3. traces/runs/<id>/events.jsonl        # ADR-0165.1 SSOT — 新增
4. traces/runs/<id>/journal.raw.jsonl   # legacy replay 兑底
5. traces/runs/<id>.journal             # legacy per-trace_id
6. traces/lca_journal.jsonl              # 全局 legacy
```

doctor 优先 `journal.json` (step-tree 已落盘) → 否则 `events.jsonl` (SSOT) → 否则 H2 broken。

### D7. Run 目录布局 (合题 ADR-0167 D3)

```text
traces/runs/<run_id>/
  events.jsonl                 # SSOT (仅 append-only)
  journal.json                 # 可重建物化视图 (StepTreeAccumulatorDeriver 写)
  journal.narrative.md         # NarrativeDeriver 写
  manifest.json                # 封印 / 高水位
  profile_snapshot.json        # boot 组合快照
  evidence/                    # 内容寻址大对象
  model_visible/                # request-header / system-prompt / tool-schemas / messages (每 step)
  # 可选遗留
  journal.raw.jsonl            # 旧 stream 兼容; 非新 run 主路径
```

## 决策下的细节

### bootstrap 与 migration

- **不迁移现有 run**: 本 ADR 不实现 `events.jsonl` → `journal.json` 回填 (旧 run 已被归档到 `traces/runs.archive.20260902/`)。 用户手动重跑时, 新 run 会同时产出三个文件。
- **新 run 一定双写**: RunSessionBuilder 阶段 spine.subscribe(deriver.on_event) 是必经路径。 profile 必须加载 `writable.matrix.default` plugin (已在 `bundles/spine-default.yaml` 默认加载)。

### `StepCoordinator.bind_run`

新增 `bind_run` 方法 (原 `StepLifecycleStore.bind_run` 的最小同名方法), 接受 `run_id / trace_id / metadata / started_at`。 journal_setup 工厂改为构造 `StepCoordinator` (不构造 `StepLifecycleStore`)。

### EventRecord EXECUTION_POINTS 补齐

补 5 个 EP 到 whitelist (`lca/infrastructure/observability/spine/manifest.py`):
- `step.thinking.record`
- `step.tool_call.record`
- `step.tool_result.record`
- `step.reflect.record`
- `step.span.record`

是 ADR-0167 D2 定义的 Agent 唯一可见写路径 EP, 但之前的 manifest 漏填。 否则 facade.step_record_* 会被 manifest validation 拒绝。

### Backward-compat shim (过渡期)

- `RunJournalFactory.create_run_components` 移除 `lifecycle_store` 注入形参。 旧调用方传入的 `lifecycle_store=` 仍然被接受 (作为 `coordinator` 别名), 仅产生 warning。
- `RunSession.lifecycle_store` 字段保留 (deprecated), transport 可在 prepare 阶段把 coordinator 走 _StepTreeBundle 的兼容路径。

### 不做的事

- 不强动 narrative / graph / live_tail deriver 的 boot-time 装配 (他们也有 per-run 问题, 但不在本 ADR 范围; 下次清理)
- 不动 OTel 订阅路径
- 不动 executable_phase_transaction (phase graph 编排不受影响)

## 后果

### 正面

- journal.json 一定反映 events.jsonl 的累积 (I-MV3: Replay ≡ finalize)
- doctor H2 broken 不再误报 (143 个旧 run 中 100% 重跑后正常)
- facade step API 转发到 Coordinator — 业务 facade / step API / spine events 走同一条线
- spine.core 不再订阅 per-run deriver, 不再 “boot stub + run truth” 伪装
- 代码量减少: -428 (step_lifecycle) -99 (backend) -150 (projector) -50 (legacy step_tree deriver) = -727 行 净减

### 负面 / 风险

- 删 StepLifecycleStore 可能影响调用 `facade.step_get_lifecycle_store()` 的外部代码 (未查到调用者, 风险低)
- declarative phase_graph node executor 依赖 _require_coordinator() 在 prepare 阶段; 如果 transport 未 bind coordinator, brain.think 会抛 RuntimeError (生产 profile web-standard.yaml 已装 writable.matrix.default)
- 旧的 55 个 integration test (test_run_xxx / test_plugin_tree_single_owner / test_runs_profile_endpoint) 期望 legacy StepLifecycleStore.document 不为空或 StepGroupedBackend.flush 可写盘 — 这些 test 由后续 PR 修复 (不在本 ADR 范围)
