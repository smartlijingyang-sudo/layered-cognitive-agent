# ADR-0260 — 强制检索与写盘铁律契约：检索是义务、写盘回执先于"已记下"

## 状态

**Proposed — 2026-10-02**

> **一句话**：Muse 侧"每次实质 turn 先强制检索记忆、说"记下了"之前必须有写盘成功回执"两条规则，LCA 侧已有两层落实——代码级写盘确认门（`acknowledgement.py`）与提示级检索义务块（`bf561ea17`）——本 ADR 把这两层都升为契约不变量，并补上缺口：检索义务的条件渲染盲区、当场写/先读后写的纪律缺席、轨迹级验收用例。

**Extends**：
- [ADR-0255](0255-muse-production-runtime-full-reference.md)（Muse 生产运行时全量参考）：本 ADR 是 0255 §4.2（强制检索决策树）与 §4.3（落笔前写盘与冲突消解）的 LCA 落地提案——对应机制已部分落地（见下），本 ADR 负责"升契约 + 补缺口"；
- [ADR-0254](0254-commercial-context-files-and-continuous-memory-runtime.md)：写盘回执机制来自 0254 落地（commit `470207a2f` "project curated memory to MEMORY.md with write receipt"）；
- [ADR-0258](0258-compaction-exemption-and-reinjection.md)（压缩豁免与重注）：C2 的"摘要丢失细节用检索链找回"与 0258 的 C2（摘要血统）同源。

**实证来源**：2026-10-02 iter-arch 轮对当前实现的实证审计——

- 已落地一（写盘确认门，代码级，升 C1 的基础）：
  - `lca/cognition/memory/acknowledgement.py`：`guard_memory_claim`/`guard_reply` —— 回复含"已记下/已记住/I've noted"类宣称但没有未被消费的成功投影回执时，直接替换为拒绝句"这条还没有写入记忆文件。我不能说已经记下。"；

- 已落地二（检索义务与写盘铁律，提示级，升 C2/C3 的基础，commit `bf561ea17` "feat(prompt): 注入 ADR-0255 强制检索决策树与落笔前写盘认知闸门"）：

  - `explain.py::explain_record` 的 memory_explain 八字段 + `supersession_chain`：冲突原地修正的 provenance 基础设施已存在；

## 0. 接任务前 7 问

1. **问题是什么？** ① 检索义务与写盘铁律已有提示级+代码级落实，但没有任何契约锁定——删门/删块不被视为破契约；② 检索义务块只在 home-bound run 渲染，存在覆盖盲区；③ §4.3 条 1/2 无机制；④ 轨迹级验收（T5/T3）缺席。
2. **受影响的事实或契约是什么？** `memory.py` 提示块的渲染条件、写盘确认门的回归红线、记忆工具的写入纪律、run 轨迹验收用例集。
3. **唯一真值在哪里？** 检索义务的真值是轨迹（是否发生 `memory_search` 调用），不是模型自称"我记得"；写盘的真值是写盘回执（`take_claim_right` 签发），不是回复里的"已记下"。
4. **改变哪个边界？** 把"检索义务/写盘铁律"从"已有实现"变成"契约不变量"（实现可重构，语义不可删）；把覆盖盲区与纪律缺席变成显式待拍板项。
5. **现有 Protocol / ADR 能否表达？** 不能。0254 定义了记忆运行时与写盘回执，但没定义检索义务；0258 定义了压缩豁免，但没定义检索/写盘纪律；`bf561ea17` 的提示块没有 ADR 背书。
6. **失败、重试、恢复和幂等语义是什么？** 写盘门保持现有 fail-closed（无回执 → 拒绝句替换）；检索义务提案 fail-open by design（见 §5 待拍板①）；冲突写入失败 → 不得另起"更正"条目掩盖，必须显式报错。
7. **如何验证？** §4 的验收用例 T1–T4。

## 1. 契约

### C1 — 写盘确认门（已实现，升不变量）

- 任何用户可见回复中出现"已记下/已记住/I've noted"类宣称时，必须持有一次未被消费的成功写盘回执（`take_claim_right()` 消费制）；
- 无回执 → 回复被替换为拒绝句，不静默放行、不改写为模糊措辞；
- 回执不可复用、不可伪造（投影管线签发，模型侧只消费）；
- 落地现状即满足（`acknowledgement.py` + `parse.py` 接线）；ADR 化后成为回归红线：**删门 = 破契约**，对应回归用例见 T1。

### C2 — 强制检索决策树（已提示级落地，升契约 + 补盲区）

- 每次实质 turn 的第一步按 0255 §4.2 决策树执行（豁免 → `memory_search` 多角度 → `memory_explain` 精读 → 常驻文件兜底 → 落空则承认缺失）；
- "觉得自己记得"不能替代检索；易变事实（价格/档期/状态）行动前必须经工具重验证——记忆只给线索不给结论；
- 检索链与压缩摘要的关系：摘要丢失的细节用检索链找回（ADR-0258 C2），**不许**把摘要当原文引用；
- **盲区（待拍板，见 §5 ①）**：当前 `memory.py` 块只在 `_has_home` 为真时渲染；契约要求要么给未绑定 run 同等义务块，要么显式声明"未绑定 run 豁免检索义务"并记录理由。

### C3 — 写盘铁律（提示块已覆盖三条，补两条，升契约）

1. **落笔前写盘**（已有）：C1 的代码门 + 提示块双重落实；
2. **冲突原地修正**（已有）：新事实与旧条目冲突 → 找到旧条目原地修正，走 `supersession_chain` 保留 provenance（谁说的、何时、替换了什么）；不许另起"更正"条目；
3. **凭证红线**（已有）：`contains_secret`/`is_private_personal` 过滤统一适用于所有写盘路径（投影管线 + `memory_add` 工具直写）；命中 → 拒绝写入并打 warning 事件，不静默丢弃；
4. **当场写**（新增）：学到 durable 事实当场写（turn 内），不攒到 turn 末；turn 内写盘失败 → 回复中不得宣称已记下（C1 兜底）；
5. **先读后写**（新增）：改 MEMORY.md/记忆记录前先读当前版（后台任务可能已改），用精确替换，保持其余部分不动。

## 2. 落地方式（提案级，细节待拍板后实施）

1. C1 现有代码不动，加回归用例（T1）锁定"删门即红"；
2. C2 的盲区决议后：要么删 `_has_home` 条件（全 run 渲染），要么在 ADR 正文记录豁免理由；补轨迹级验收 T2/T3；
3. C3-4/C3-5 追加进 `memory.py` 提示块（"记忆写入与写盘铁律"追加两行）与 `memory_add`/`memory_update` 工具描述；C3-3 的过滤调用点统一审计一次（确认 `memory_add` 直写路径同样经过滤）。

## 3. 非目标

- 不给检索义务加 wire gate（§5 ① 提案 fail-open by design，理由见下）；
- 不改 `take_claim_right` 的消费语义与拒绝句文案；
- 不要求历史记忆补 `supersession_chain`（C3-2 只约束新写入）；
- 不碰 `bf561ea17` 的"至少 3 个角度"措辞（比 0255 更严格，保留）。

---

## 4. 验收用例

- **T1**：无写盘回执时构造含"已记下"的回复草稿 → 输出为拒绝句；有回执时原样放行；同一回执第二次使用 → 拒绝（消费制）；
- **T2**：冷门事实问答 run 轨迹：首轮回答前必须出现 `memory_search` 调用；直接答对但无检索记录 = 不合格（0255 T5；与 backlog todo-2 的真实 run 复核合并执行）；
- **T3**：易变事实（价格/档期）场景：轨迹中必须出现重验证工具调用，仅凭记忆断言 = 不合格；
- **T4**：冲突写入场景：旧条目被原地修正且 `supersession_chain` 含新旧两条；另起"更正"条目 = 不合格；含密钥的写入被拒绝并打 warning 事件。

## 5. 待拍板（arch 轮不擅自决定）

1. **检索义务 fail-open 还是 fail-closed**：提案 fail-open（未检索 → 允许回答，但提示块要求标注"未经检索"的不确定性），理由：① "实质 turn"无法机械判定，wire gate 误杀率高（豁免类难穷举）；② 0255 本身把检索定义为"义务"而非门禁。若选 fail-closed，需先定义"实质 turn"的可判定规则；
2. **C2 盲区**：`memory.py` 块只在 home-bound run 渲染——是故意设计（未绑定 run 无记忆可查）还是覆盖遗漏？若是前者，在 ADR 正文记录豁免理由；若是后者，删 `_has_home` 条件；
3. **C3-4 当场写 vs 后台做梦管线**：0254 的做梦管线是后台固化；"当场写"与后台固化的边界（哪些事实必须 turn 内写、哪些可延后）需拍板；
4. **C3-3 过滤的拒绝粒度**：命中秘密是整条拒绝还是脱敏后写入？当前提案整条拒绝 + warning 事件。

## 6. 决策记录（2026-10-02，李超授权 Athena 按 muse 思想裁决）

1. **检索义务：fail-open by design（维持提案），未检索 → 回答必须标注“未经检索”的不确定性**。理由：muse 思想不是“一律 fail-closed”——fail-closed 只用在**可精确判定**的地方（如 C1 写盘回执是精确可判定的，所以 fail-closed）；“实质 turn”无法机械判定，wire gate 误杀率高，诚实的工程选择是 fail-open + 显式标注。这个区分本身就是本 ADR 要沉淀的方法论。
2. **C2 盲区：是覆盖遗漏，不是故意设计**。裁决：删 `_has_home` 条件，改为全 run 渲染——未绑定 run 渲染“本次会话无持久记忆可用”声明块。理由：fail-closed 方向是“不许模型在没有记忆源时假装有记忆”；“无记忆可查”不是豁免检索义务的理由，而是必须显式声明的前提。
3. **当场写 vs 做梦管线边界：给了用户即时承诺的事实 → 当场写（turn 内）；未承诺的残差信号 → 做梦管线**。理由：边界 = 是否对用户做了持久承诺——C1 的 say-do 门已确立“承诺→回执”语义，当场写是同一语义在时间维度的展开；0254 §2.2 的 EPHEMERAL_FAST 本来就是为“未承诺信号”设计的，两者互补，直接引用不另发明。
4. **凭证过滤拒绝粒度：整条拒绝 + warning 事件**（维持提案，不选脱敏写入）。理由：凭证红线是最高优先级的 fail-closed；脱敏写入制造“部分记忆”幻觉（模型以为记下了完整事实）——比不记更危险。
