> 这是 ADR-0168 的 follow-up。**保留 ADR-0168 作为"问题陈述与现状盘点",决策方案整体迁移到本 ADR**(supersedes ADR-0168 的"决策"段)。原 PR 计划迁移到 `docs/plans/2026-09-02-spine-step-remediation/0168.1-main.md`。

## 一句话

把 ADR-0168 引入的 12 个控制面(`LoopStepControl` + `coord.record_*` + `coord.emit_phase` + `event_emission hook` + `facade.step_*` + `terminal.materialize` 等)收敛为**一个状态机 `LoopCursor`**。业务路径只允许两个动作:`advance(phase)` 与 `record_*(...)`,其余(step / segment / request / flush / close 顺序)由状态机自动派生。

## 背景

ADR-0166 / 0167 / 0167.1 已把"切步责任交给 loop"写进规范,但只切到 step 这一层。**segment(think / act)、phase(perceive/think/gate/act/reflect/...)、iteration(重试预算)** 三层仍要求调用方人工协调:`safe_executor._open_act_step` 同时调 `loop_control.open_segment` / `coord.record_tool_call` / `coord.emit_phase` —— 一段普通工具调用要在 5-6 个组件间协调。

ADR-0156 ~ 0162 这 7 个连续修补都是同一故事:业务路径加 / 改,**漏了 emit / emit 多 / emit 错时序**。修补序列本身证明现状在漏;ADR-0168 PR-1 仅收 step 一扇窗,segment / phase / record / request 四扇窗仍开,控制面只增不减。

ADR-0168 已识别到 `event_emission._derive_step_completed` 双轨残留(facade.record + coord.emit_phase),但 PR-4 的解法是"hook 改用 spine"——还是在 hook 层打补丁,未触根。**根因在 hook 层:hook 是事件投影层的辅助设施,把它当成状态机来用是范畴错误**。

ADR-0093(Continuous Control Plane)与 ADR-0095(Loop-Guard Locality)早说"cursor 才是真相,hook 只是投影"——ADR-0168.1 是把这两条原则正式落到状态机层。

## 决策

### D1 · 状态机本机

```python
# contracts/observability/loop_cursor.py  (新)
from typing import Literal, Protocol
from dataclasses import dataclass

PhaseName = Literal[
    "perceive", "think", "gate", "act", "reflect", "remember", "stop"
]
CloseReason = Literal[
    "completed", "user_stop", "budget_exhausted",
    "approval_pending", "approval_rejected", "error", "loop_guard"
]

@dataclass(frozen=True)
class CursorSnapshot:
    """read-only 视图;reducer / projection 消费。"""
    step_id:         str
    iteration:       int           # 外层重试轮次(⊃ ADR-0095 iteration)
    attempt_in_step: int           # step 内重试
    phase:           PhaseName
    stop_signal:     CloseReason | None

class CursorError(Exception):
    """非法转移 / 关闭后调用 / 跨窗口 record → raise,不静默 fallback。"""

class LoopCursor(Protocol):
    """loop 单一状态机 (ADR-0168.1)。
    业务路径唯一允许做的:advance + record_*(...) + close。
    begin_step / end_step / open_segment / close_segment / emit_phase / flush / subscribe
    一律不暴露在公共面。
    """

    # --- 1 个属性:读 ---
    @property
    def snapshot(self) -> CursorSnapshot: ...

    # --- 转移 (3) ---
    def advance(self, phase: PhaseName) -> CursorSnapshot: ...
    def halt(self, reason: CloseReason) -> None: ...
    def close(self, reason: CloseReason) -> None: ...

    # --- 事实记录 (4) ---
    def record_thinking(self, payload: ThinkingRecord) -> None: ...
    def record_tool_call(self, payload: ToolCallRecord) -> None: ...
    def record_tool_result(self, payload: ToolResultRecord) -> None: ...

    # --- 横切 (2) ---
    def record_request_header(self, header: RequestHeader) -> None: ...
    def fork(self, reason: Literal["child_agent", "delegation"]) -> "LoopCursor": ...
```

**为什么是 9 + 1,不是 6 也不是 12**:见迁移计划 §C"对账";逐一对应 ADR-0168 控制点,逐个决定**保留 / 删** 的理由是状态机内 / 外。

### D2 · 状态转移图

```text
                  ┌────────────────────────────────────────┐
                  │            OUTSIDE_LOOP                │
                  └────────────────────────────────────────┘
                                  │ cursor.advance('perceive')
                                  ▼
                  ┌────────────────────────────────────────┐
                  │  PERCEIVE  (phase window open)         │
                  └────────────────────────────────────────┘
                                  │ advance('think')
                                  ▼
                  ┌────────────────────────────────────────┐
                  │  THINK  (segment.think 隐式)           │◀──┐
                  └────────────────────────────────────────┘   │ retry in step
                                  │ record_thinking            │
                                  │ advance('gate')              │
                                  ▼                              │
                  ┌────────────────────────────────────────┐   │
                  │  GATE                                       │
                  └────────────────────────────────────────┘   │
                                  │ (gate 通过)                  │
                                  ▼                              │
                  ┌────────────────────────────────────────┐   │
                  │  ACT  (segment.act 隐式)              │   │
                  └────────────────────────────────────────┘   │
                                  │ record_tool_call              │
                                  │ advance('reflect')            │
                                  ▼                              │
                  ┌────────────────────────────────────────┐   │
                  │  REFLECT                                  │
                  └────────────────────────────────────────┘   │
                                  │ (maybe remember)             │
                                  │ advance('stop') ─────────────┘
                                  ▼
                  ┌────────────────────────────────────────┐
                  │  STOP  (close_iteration)               │
                  └────────────────────────────────────────┘
```

- **step** 边界由 LLM 调用源 hook 派生,不是显式 `begin_step`。`record_request_header` 调用一次 = 一次 step 起点。
- **segment** 边界由 phase 派生:phase = think/act 时,自动归 segment.think / segment.act。业务路径**不显式开段**。
- **phase** 是真窗口,由 `advance()` 控制。同 phase 重复调用 idempotent。
- **iteration** 是外层重试(⊃ ADR-0095 iteration);`attempt_in_step` 是 step 内重试,二者独立计数。

### D3 · 不变量

| 编号 | 内容 | 谁保证 | 验证 |
|---|---|---|---|
| L1 | 任何 `writable.step.*` EP 必有 begin/end 配对 | cursor (LLM hook + close) | grep events.jsonl 配对数 == begin 数 |
| L2 | `writable.segment.*` 同上 | cursor (phase 转移派生) | grep segments 配对 |
| L3 | `phase.*` EP 严格按 D2 转移图顺序 | cursor (非法 phase = CursorError) | 转移图单测 |
| L4 | 业务代码不 import EventSpine / Serializer / Storage | importlinter `business-event-isolation` | `uv run lint-imports` |
| L5 | `record_*` 必在某个 phase 窗口开时调用 | cursor (不在窗口 = CursorError) | cursor 单测 |
| L6 | 任何 LLM 调用必在 step 内且必产生一次 `llm.request.header` EP | cursor (在 step 外调 raise;hook LLM adapter) | run 实测 + verify-model-visible |
| L7 | terminal flush 顺序:`关状态机 → flush coalescer → close storage → flush derivers → emit close EP → release` | `cursor.close()` 内部步骤编号 | unit test `terminalize_cursor_close_order` |
| L8 | iteration ⊃ ADR-0095 iteration(外层 ⊃ inner);`attempt_in_step` 与 `iteration` 独立计数 | cursor 状态 | 单测覆盖二阶重试 |

> L5/L6 是 ADR-0168 没说的;L8 是 ADR-0094/0095 与本 ADR 的 cross-ref 钉死。

### D4 · Payload(frozen dataclass)

```python
# contracts/observability/loop_cursor_payloads.py  (新)
@dataclass(frozen=True)
class ThinkingRecord:
    content_digest: str
    content_path:   str | None
    token_count:    int | None

@dataclass(frozen=True)
class ToolCallRecord:
    tool_name:        str
    args_digest:      str
    args_payload_path: str | None    # model_visible 5 件套

@dataclass(frozen=True)
class ToolResultRecord:
    tool_name:     str
    result_digest: str
    result_path:   str | None
    outcome:       Literal["ok", "failure"]

@dataclass(frozen=True)
class RequestHeader:
    """cursor 注入 step_id;业务路径不能填。"""
    step_id:             str
    reason:              Literal["initial", "next_step", "series", "change", "inherited"]
    model:               str
    system_digest:       str; system_path:       str
    tools_digest:        str; tools_path:        str
    messages_digest:     str; messages_path:     str
    manifest_digest:     str; manifest_path:     str
    inherited_from_step: str | None = None
```

**关键**:`step_id` 不让业务路径填——cursor 注入。这条结构性禁掉"在错的 step 里吐 fake 记录"。

### D5 · L7 close 顺序(死约束)

```text
cursor.close(reason) 走五步,顺序不可颠倒:

  1. 关状态机
       ├─ advance('stop') 完成;当前 step/segment/phase 窗口 emit window_end
       └─ 后续 record_* / advance 抛 CursorError

  2. flush writable faces
       ├─ coalescer.flush()           # L7-2
       └─ storage.close()             # L7-3:必在 coalescer 后

  3. flush derivers
       ├─ step_tree_deriver.flush()  → journal.json
       ├─ narrative_deriver.write_document(...) → narrative.md
       └─ graph_deriver.flush()      → phase_graph.dot

  4. emit 'writable.iteration.close' EP(带 reason)  # L7-5:最后一次写入

  5. release
       ├─ unhook LLMCallHook
       ├─ clear ContextVar (loop_cursor)
       └─ snapshot freeze ("closed")
```

异常路径(`error` / `halt → close` / `close 被多次调用`)见实施计划 §3.2。

## 不变量承接与新引入

| 既有 | 本 ADR 处理 |
|---|---|
| C1 闭集(认知闭环) | 不变;`PhaseName` 是 `Literal[...]`,编译期禁扩展 |
| C2 双平面 | 不变;cursor 是认知面的状态机,执行面仍只读 snapshot |
| C3 Journal | 不变;cursor 派生 EP,Journal 仍是 SSOT |
| C4 Reducer | 不变;reducer 只读 `snapshot`,不改它 |
| C5 能力衰减 | cursor.fork 内置 grant 校验 |
| C7 控制/观察分离 | **强化**:cursor 是 control face;event/trace/metrics/projection 不混进 cursor |
| I-PLUG1(业务不 import spine) | **强化**:cognition/body/runtime/agent 不 import `coord.*`,只 import cursor |

## 兼容性

- `coord.emit_phase` / `coord.record_*` / `coord.begin_step` / `coord.end_step` / `coord.record_request_header` 在 facade 留 `@deprecated` 1 版本;`redirect` 到 cursor。**importlinter 抓 cognition/body/runtime/agent 这几层直接调用 coord**。
- `event_emission._derive_step_completed` **整段删除**,不保留 deprecation wrapper(hook 是 PRD 的次优层,不留兼容尾巴)。
- `facade.step_*` 6 个方法沿用 ADR-0168 PR-6 的 `@deprecated` 1 版本策略。
- 不开 `LoopStepControlAdapter` 套 cursor;一次性切完,不平行机制。

## 删除条件

- `coord.emit_phase` facade wrapper:1 个 release 版本后删(无业务调用方 = grep `coord.emit_phase` 在 lca/cognition + lca/body + lca/runtime 为 0 时)。
- `coord.record_*`:同上。
- `facade.step_*`:同上。

## 后果

### 正面

- 控制面从 12 个 → 1 个(状态机)。业务路径从"协调 5-6 件事"降到"2 个动作 + 不越界"。
- step / segment / phase / iteration 四层都靠状态机派生,**修补序列(ADR-0156~0162)同类问题不再发生**。
- L7 close 顺序封装:`terminal.materialize` 不再是胶水层,只调 `cursor.close()`。
- 业务路径不接触 `flush / subscribe / emit_phase`,结构性禁掉回头路。

### 负面

- `StdLoopCursor` 是新增组件,bug 影响范围大;但比 hook 散弹好测,转移图 12 边全列在 D2。
- 老的 `coord.emit_phase` / `coord.record_*` 调用方改造一次;但都是局部替换,facade 重定向已分担工作。
- `iteration ⊃ ADR-0095 iteration` 的口径需要 ADR-0095 同步补一行说明(见引用)。

### 不在本 ADR 范围

- ❌ `spine.deriver.metrics`(Prometheus)— 单独 PR
- ❌ 删 `journal.py` 49 事件类(保留 readonly dataclass)
- ❌ `spine.deriver.otel_trace` plugin wrapper
- ❌ OTel / Langfuse 投影路径
- ❌ 6 个非 web-standard profile 的 spine 装配(PR-10)
- ❌ **`fork()` 实装** —— C5 口子,本 ADR 留 surface 占位,实施计划阶段再开
- ❌ **`halt` 的 resume 协议** —— 仅留 surface;resume 链路由 boot/spawn 决定
