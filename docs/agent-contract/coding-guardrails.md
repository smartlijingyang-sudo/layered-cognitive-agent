# 代码工程守则(SSOT 展开层)

> 本文件是根 `AGENTS.md` §1.5 的展开层。根文件是 standing rule 的唯一正文入口,本文件负责 LCA 特定落地、反例和引用清单。**改规则先改根,再同步本文件。**

## 何时读本文件

- 接到的任务涉及改代码 / 写代码 / 重构,且根 AGENTS.md §1.5 的 7 条 standing rule 有任一条你不确定怎么落地时
- 写完一段代码,准备自检"这是否符合长期可维护"前
- 评审他人 / 自己 PR 时,需要一份对照清单

## 1. 第一性原理

**为什么:** 缺这一步,后面所有工作都是"按习惯写",碰到边界就改不动。

**落地步骤(每条写代码任务必走):**
1. 用业务/系统行为重述需求,不引用任何实现名词
2. 标出所有跨越的边界:层、seam、控制面/观察面、进程、外部系统、信任边界
3. 写出可逆/不可逆:哪些选择改了容易回,哪些不可回(不可回的多想一步)

**失败信号:** 上来就贴相似代码 / "这跟 X 类似所以..." / 没列边界就开始改。

## 2. 直击本质

**为什么:** 修症状的代码必然短命;症状会换皮,根因不变。

**落地:**
- 找 root cause,不在表面包装。同一根因第二次出现 = 上次没修对。
- 一次修一处根因;不附带"顺手优化"。
- 修完问一句:这条 PR 删掉,问题会以原样回来吗?会 = 没修对。

**LCA 落点:** 详见根 AGENTS.md §2.2(事实/状态/决策/许可/回执/投影六分类)。分类错了 = 没找到本质。

## 3. 架构优雅

**为什么:** seam 没标清,后面所有依赖方向都要靠"大家自觉",不可持续。

**落地:**
- 跨边界前先写 seam:网络边界、进程边界、信任边界、所有权边界
- 单一职责:一个模块一句话能说清"我是干嘛的";需要"和"= 拆
- 依赖单向:谁也不允许反向 import;同层通过公开 API,不偷穿
- 按领域分组,不按技术层(`billing/` 优于 `services/+models/+controllers/`)

**LCA 落点:** 根 AGENTS.md §2.1 单向依赖层;lint-imports + check_package_contracts.py 守护。

## 4. 模块化

**为什么:** 不按概念切,后续每次改动都会牵动不相干的代码。

**落地:**
- 一个模块一个概念,暴露小而稳定的 surface;内部随便改
- 依赖只指向一个方向,不通过兄弟模块绕开公开 API
- 真正需要插件点的位置:至少两个实现,或具体到能想象出第二个;否则是噪音
- 一起改的代码要挨着放

**LCA 落点:** 根 AGENTS.md §3 C6(最小化);plugin 硬约束见根 AGENTS.md §5。

## 5. 设计模式

**为什么:** 模式是消解成本的工具,不是装饰;没成本的模式 = cargo。

**落地:**
- 只在模式能消解具体成本时引入;不为了"显得专业"贴模式
- 组合优于继承;数据优于控制流;能选标准库原语就选标准库
- 两个相似结构是巧合,第三个相似结构才抽
- 用模式是为了让代码更易读,不是为了证明你懂模式

**失败信号:** 类名带 `Manager` / `Helper` / `Utils` / `Handler` 但说不清负责什么。

## 6. 长期可维护

**为什么:** 代码被读的次数远大于被写的次数;不可测试 = 耦合过紧。

**落地:**
- 注释只解释 *为什么*,不解释 *是什么*;需要注释解释 *是什么* = 重写代码
- 测试是设计的一部分;无法独立测试的改动 = 耦合太紧
- 留下略好于接手时的状态:把读不懂的改名,把不要的删掉,把可读的收紧
- 每个新依赖 / 抽象 / 配置项,必有 owner + delete-when。无 owner = 永久债

**LCA 落点:** 根 AGENTS.md §5(变更闭环);根 AGENTS.md §6(验证矩阵);每个 bugfix 至少一个回归测试。

## 7. 不做临时代码

**为什么:** 临时方案没有"临时"——会留下来,污染后续每一代。

**落地:**
- 兼容 shim 引入的同一 PR 必须同时删除(根 AGENTS.md §4 已强制);无 delete-when = 红灯
- "先这样以后再改" = 不;先停下来评估是否真的需要兼容期,owner/验证命令/删除时间点写进同一 PR
- 双写 SSOT 只在 COMPAT 期内允许;新代码默认 `to`,不引入旧用法
- 离开前卫生:无新增无期限 TODO、无死代码/死 import、类型标注完整、提交信息说清"做了什么/为什么"
