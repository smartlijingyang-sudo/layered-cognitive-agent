# ADR-0246 M2-M4: 用户机器副作用平面全流程设计方案

**Status:** Approved — 2026-09-20
**Scope:** ADR-0246 M2 (控制面配对), M3 (Local Companion 客户端), M4 (前端 UI 交互与端到端闭环)

---

## 1. 架构目标与职责划分

1. **Gateway 控制面 (M2)**
   - 遵循 RFC 8628 Device Code 配对流程，管理 `device_code`、`user_code`、`machine_token`。
   - 提供端点：
     - `POST /api/device/pair/code`
     - `POST /api/device/pair/verify`
     - `POST /api/device/pair/poll`
   - WebSocket `/api/device/ws` 支持已配对机器的安全接入、心跳维持、Job envelope 投递与结果回传。

2. **本地 Companion 客户端 (M3)**
   - 提供 `scripts/lca-companion` 可独立执行工具。
   - 流程：申请配对 -> 终端展示 8 位 `user_code` -> 轮询并存储 `machine_token` -> 建立出站 WebSocket 长连接 -> 监听 `tool_call` -> 本地刚性核验 `CapabilityGrant` -> 真实调用操作系统命令并生成 `EffectReceipt` 回传。

3. **前端 UI 补丁集成 (M4)**
   - 遵循 LCA 守则（禁止直接修改 `lobehub-ui/`，统一经 `deploy/lobehub/patches/` 管理）。
   - 在前端补充设备绑定卡片，调用 `/api/device/pair/verify` 完成配对。
   - 与现有 `HeteroDeviceSwitcher.tsx`（已包含“用电脑/云沙箱/自动”）联动，展示已配对的本地设备及在线状态。

4. **端到端集成测试**
   - 真实链路回放：Companion 申请配对 -> 前端提交配对码 -> 机器在线 -> LocalExecPort 下发命令 -> Companion 真实执行 -> 生成 EffectReceipt -> 校验回执与 Journal。
