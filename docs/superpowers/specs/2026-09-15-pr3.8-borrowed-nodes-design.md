## 0. Motivation

The three Phase-Graph Node Orchestration docs (`00-inventory.md`, `01-industry-matrix.md`, `02-proposed-graph.md`, `03-six-column-0206.md`) inventoried the production graph and mapped 40 industry capabilities to LCA seams. The inventory surfaced seven typed-boundary nodes that the three docs label `**ADD**` (P0/P1) but the implementation tree has not landed:

| Node | Phase | Industry source | Priority |
|---|---|---|---|
| `think.budget.check` | think | DSH pre-step waterfall, OpenAI `max_turns`, Hermes token/cost | P0 |
| `think.context.compact` | think | DSH / Hermes compaction, recovery-before-model | P0 |
| `think.decision.repair` | think | Coding-agent truncated JSON, schema repair | P1 |
| `act.fanout` | act | DSH / LangGraph Send, parallel `tool_calls` | P1 |
| `act.join` | act | DSH / LangGraph Send, parallel-tool join barrier | P1 |
| `act.approve.gate` | act | Hermes / OpenAI Agents, dangerous-tool HITL | P1 |
| `act.result.normalize` | act | ReAct / Hermes observation normalize | P1 |

Each is a typed-boundary node placed inside an existing phase region (think or act) or sibling region (intervene) — none introduces a new phase, none re-shapes the outer control topology, none touches the Gate⊂Think invariant, none duplicates the effect-gateway-only world side-effect path. They close the gap between the inventory's "what's missing" and the actual `lca/nodes/` tree.

This PR series lands them as **seven independent PRs**, each small enough for a single subagent (per `using-superpowers:dispatching-parallel-agents`), each self-contained (no cross-PR stub or placeholder), each closing with its own verification command set. The overview doc tracks dependency order; each PR's plan file lists its own predecessor.

## 1. Design overview

### 1.1 Architectural thesis

1. **Single outer control spine.** The outer `phase.main.outer` remains the production control loop; this series does not change edges in the outer YAML. Each new node is wired into its phase subgraph only.
2. **Merge before add.** Where two nodes express the same seam (none here — `act.approve.gate` is its own seam, `act.result.normalize` is a different seam from `act.observe`), we do not add parallel factories. Each PR scans for parity first.
3. **No new phase, no new EP name, no foreign tokens in node ids.** This series is node-additive inside existing regions.
4. **Each PR is self-contained.** No placeholder stubs across PRs. `act.fanout` and `act.join` land with their bundle wiring restricted to the 1:1 path (one envelope in → one envelope out → one receipt in → one receipt out); the N:N parallel wiring is a deliberate later PR when a profile needs it.
5. **Each PR reuses the typed-boundary contract** from ADR-0227 §Decision + ADR-0219 §5.5: hand-written `@plugin(...)` carrier (PR-3.7.a retired `@graph_node`), `declared_inputs` / `declared_outputs` typed at compile time, `NodeInput` / `NodeOutput` shape frozen.

Each file: one node, one `@plugin(...)` carrier, declared IO, four-test minimum (happy / missing / idempotent / type assertion). Pattern mirrors `lca/nodes/think/route/decide.py` (PR-3.6 reference).

### 1.3 Invariants (held by every PR in this series)

1. **AGENTS.md §3 C1 (cognitive closed set)**: no new phase, no new EP name. The closed six-phase set is unchanged.
2. **AGENTS.md §3 C2 (double-plane)**: cognition does not write the world; execution does not rewrite cognition. None of these seven nodes crosses that line.
3. **AGENTS.md §3 C4 (Reducer single-writer)**: none of these seven writes `AgentState`. They emit typed ports that the Reducer / projection folds consume.
4. **AGENTS.md §3 C5 (capability monotonic)**: `act.approve.gate` is the only one that touches capability; it must remain monotonic and must not become a second effect gateway. All other six do not read or grant capabilities.
5. **AGENTS.md §3 C10 (execution narrow door)**: `act.fanout` and `act.join` orchestrate `CommandEnvelope`s; they do not execute. Execution remains `effect.execute → Body → SafeExecutor → Sandbox`. `act.result.normalize` does not re-execute; it normalizes an existing `EffectReceipt`.
6. **AGENTS.md §3 C11 (event closed set)**: if a node emits an EP event (none of these seven need to), the EP whitelist must be updated in the same PR + SpineHandler registered + test added.
7. **AGENTS.md §3 C13 (information lineage closed)**: every node carries `declared_inputs` / `declared_outputs` typed at compile time; cross-node data flow passes through typed ports; no stringly-typed attribute access.
8. **AGENTS.md §4 (no COMPAT shim)**: each PR deletes any existing parallel mechanism in the same PR. `act.result.normalize` is additive (no parallel normalizer today), so no delete; the rest are additive too.
9. **AGENTS.md §5 (change closed loop)**: every PR updates bundles + tests + docs + `lint-imports` + plan tree + boot-check + the relevant `lca-ops` audit.
10. **ADR-0225 (no per-node max_visits)**: `think.budget.check` honors this — budget lives on outer edges and in `BudgetLedger`, not as a per-node counter.
11. **ADR-0219 §5.5 (typed-port contract)**: predicate expressions over port names, no `_ResultView.__getattr__` fallback.
12. **ADR-0228 (subgraph seams)**: `act.approve.gate` lives under `phase:intervene` (sibling region carved out by ADR-0228), not as act-phase pollution.

### 2.1 `think.budget.check`

| Aspect | Value |
|---|---|
| Region | `phase:think` |
| Position in waterfall | after `think.route.decide`, before `think.context.compact` (when miss path) / `think.history.assemble` |
| `declared_inputs` | `("state",)` |
| `declared_outputs` | `("routing",)` |
| Port types | `routing: RoutingDecision` with `next_node ∈ {"think.context.compact", "terminal.commit"}` and `reason ∈ {"budget_ok", "budget_exceeded_turns", "budget_exceeded_tokens", "budget_exceeded_cost"}` |
| Read SSOT | `BudgetLedger` (existing capability port from ADR-0197 guard-stack); never reads env / time directly |

| Idempotency | Yes — same `state` ⇒ same `routing` |
| Tests (4 minimum) | (1) budget_ok → continue, (2) max_turns exceeded → stop, (3) token cap exceeded → stop, (4) cost cap exceeded → stop |

## 3. Open design questions (resolved in this spec)

### 3.1 fanout/join wiring — why 1:1 only?

The 03-six-column-0206 M1 attachment §3 ("fanout") says: "N 路必须配 join；部分失败域编译期声明（全停 / 部分承认+审计 / HITL）；禁无 join 的 fanout". Putting both into the same PR is one option. The other is to land each with the 1:1 degenerate case — `envelopes[0] = envelope` / `receipts[0] = receipt` — which:

- Honors the rule (fanout has a join downstream).
- Avoids cross-PR stubs (each PR is self-contained).
- Defers the partial-failure policy (which needs Gate cooperation + a profile that actually uses parallelism) until a profile demands it.

This spec picks **1:1 only**, with a follow-up PR planned for the partial-failure domain (see overview doc).

### 3.2 `act.approve.gate` region — why `phase:intervene`, not `phase:act`?

The intervene region is a **sibling subgraph**, not a 7th phase (ADR-0228 §3). Placing approval here keeps the act subgraph's 5-step core (`validate → authorize → envelope → dispatch → observe`) clean: `act.authorize` emits `needs_approval=True`; the outer edge routes to `act.approve.gate` (sibling); on resume, the edge routes back to `act.envelope`. Polluting `phase:act` with an approval node would put the same logic in two places (since `intervene.interrupt` already exists from PR-3.7.c).

### 3.3 `act.result.normalize` — separate node, or fold into `act.observe`?

`act.observe` already normalizes `EffectReceipt → (receipt, should_terminate)`. Adding `act.result.normalize` as a separate node duplicates the normalization step. **Two options:**

- **(a) Merge**: fold normalize into `act.observe`; do not land `act.result.normalize` as a separate node.
- **(b) Separate**: keep `act.observe` thin (receipt → receipt, observe only does the RunFact / EP-end); `act.result.normalize` does the schema/spill normalization.

The 03-six-column-0206 table lists `act.observe ∪ reflect.observation.build → concept.observe.normalize` as a merge target. Following that: **option (a) — fold normalize into `act.observe`, do not land this PR**. The overview doc records this decision and the merge target.

**Resolution:** `act.result.normalize` is **dropped from this PR series**. The PR-3.8.7 slot in the overview is repurposed to "merge normalize into `act.observe`". This keeps the count at six PRs plus one merge, not seven nodes.

## 4. Compatibility, deletion, and verification

Each PR in this series is **additive only** — no existing parallel mechanism is replaced. `act.result.normalize` is folded (option §3.3), not shimmed. Therefore no shim, no delete-when across PRs.

## 5. Anti-goals

- Do **not** add a seventh phase. Do **not** add an EP name. Do **not** introduce a foreign product token in node ids (per AGENTS.md §4 N9).
- Do **not** add per-node `max_visits` (ADR-0225). Budget lives on edges / `BudgetLedger`.
- Do **not** land fanout/join N:N semantics in this series. The N:N barrier + partial-failure domain is a follow-up PR when a profile needs parallelism.
- Do **not** land `act.approve.gate` as an act-phase pollution. It lives under `phase:intervene`.
- Do **not** create `act.result.normalize` as a separate node. Fold into `act.observe`.
- Do **not** introduce a parallel edge SSOT, a second outer loop, or a checkpointer product (per `00-inventory.md` smells 1, 3, 5).
- Do **not** skip the bundle wiring for any node. Each PR must end with the node actually reachable from `web-standard`.
