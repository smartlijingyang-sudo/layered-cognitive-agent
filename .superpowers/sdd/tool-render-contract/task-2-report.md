## Design decisions

1. **COMMON schema extensions** — Added fields needed by sandbox APIs (create_directories, command_id, operations, etc.) as reusable entries rather than inline-only FieldSpecs. `content_arg` uses python_key `content` with source `argument` to distinguish from `content` (source `observation`).

2. **sandbox_contracts.py** — Single file registers all dynamic-tool contracts. Cloud contracts defined explicitly; local contracts generated by iterating cloud contracts with `local_` prefix. Import guard (`if _name not in REGISTRY`) prevents double-registration.

3. **Skill tool renames** — `skill_id` in COMMON already has wire_key `id`. For activate_skill, `.rename('name')` maps to LobeHub's `name` parameter. For read_reference, `skill_id` stays as wire_key `id` (matching readReference's LobeHub spec).

## No behavioral changes

- No Tool's `execute()`, `validate()`, `name`, `description`, or `parameters` modified.
- No emission logic changed (that's Task 3).
- Contract registration is additive — REGISTRY entries don't affect tool dispatch.
