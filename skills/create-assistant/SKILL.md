# create-assistant

把「我想创建一个助理」变成一次设置完成的创建流程。原则：**选项优先、输入最少**——能让用户点选的绝不要求打字。

## 前置检查

- 工具列表里**必须有** `create_assistant`。没有 ⇒ 当前部署未启用助理能力（需 `web-assistant` profile），直接告知用户，不要尝试其它方式创建，也不要假装成功。

## 角色模板（单选）

| template_id | 角色 | 一句话能力 |
|---|---|---|
| `assistant.research` | 研究助理 🔍 | 资料搜集、交叉核验、带引用的研究报告 |
| `assistant.writing` | 写作助理 ✍️ | 起草、润色、结构化成稿 |
| `assistant.coding` | 编程助理 💻 | 读写代码、调试、解释实现 |
| `assistant.translation` | 翻译助理 🌐 | 中英互译、本地化、术语一致 |
| `assistant.daily` | 日程助理 📅 | 计划、提醒清单、阶段性总结 |
| `assistant.default` | 通用助理 🤖 | 问答、整理信息、协助日常任务 |

## 流程

### 1. 判断是否可以直接创建

用户一句话已说清「名字 + 角色/职责」（例：「创建一个叫小研的研究助理」）⇒ 跳过提问，直接到第 3 步。

### 2. 交互式收集（`askUserQuestion`，每轮最多 4 个问题、每题 2-4 个选项）

第一轮（角色）：
- 问题 1：「想要什么类型的助理？」选项：研究助理 / 写作助理 / 编程助理 / 其他类型。
- 用户选「其他类型」⇒ 追问一轮：翻译助理 / 日程助理 / 通用助理 / 完全自定义（此时请用户用一句话描述角色）。

第二轮（名字与画像，可合并为一轮提问）：
- 问题 1：「助理叫什么名字？」选项给建议名（如「研究助理」「小研」）+「自定义」。用户选自定义后让其直接回复名字。
- 问题 2（可选，跳过不阻塞）：「简单说说你的偏好，方便助理记住你」——用户给出一句话画像则作为 `seed_user_md`；跳过则不传。

规则：
- 每轮提问都要把「跳过/默认」做成可点选项，不强迫打字。
- 用户任何一步用文字直接给出答案 ⇒ 采纳，不再重复问。

### 3. 创建

调用 `create_assistant`：

```json
{
  "name": "<确认后的名字>",
  "description": "<一句话职责：角色能力 + 用户补充>",
  "template_id": "<上表 template_id>",
  "seed_user_md": "<可选：用户画像，写成 '# USER\\n\\n...' 的简短段落>"
}
```

失败处理：工具返回错误 ⇒ 把错误原文告知用户；同一参数最多重试 1 次。

### 4. 汇报（必须包含全部要素）

成功后回复用户：

- 助理名字 + emoji；
- 角色与能力（用模板的一句话能力 + 用户补充的职责）；
- `assistant_id`（`asst_` 开头）；
- 前端入口：`frontend_url` 非空 ⇒ 给出 `/agent/<agent_id>` 链接，说明可在助理列表找到并直接对话；`frontend_url` 为空 ⇒ 说明后端已创建成功、前端注册未完成，可稍后重试；
- 提示：和它对话时它会以自己的角色人设回应；首次对话可以补充更多个人偏好。

## 禁止

- 不要用 `run_command` / 脚本在磁盘上手写助理目录——创建只走 `create_assistant` 工具（后端 catalog 负责 digest 与事件）。
- 不要编造 `assistant_id` 或前端链接；只报告工具返回值。
- 不要在用户没确认名字前创建。
